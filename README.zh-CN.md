AI 助手会在最新回复下按仓库显示快捷引导：添加远端、发布分支、设置跟踪、获取远端、工作区、分支地图与远端管理。入口复用已有表单，点击时重新核对状态；不会直接提交或推送。修复前置条件后可点「继续处理」，检查草稿后自行发送。连接与计划失效错误提供设置、刷新或重新准备入口；刷新恢复聊天与引导，但不重开确认表单。

**看见代码之间的工作流。** MeGit 是本机 Git 工作台。一个工作流对应一张画布，仓库是节点，代码整合、开发依赖与交付方向是连线。

## 启动

### Windows 桌面版

运行 Windows x64 安装包，在开始菜单打开 **MeGit**。桌面版内置 MeGit 所需的 Node.js，不用在用户电脑上编译；Git 功能仍使用系统安装的 Git for Windows。[安装、数据迁移与打包说明](desktop/README.zh-CN.md)。

### 浏览器版

需要 Node.js **22.12 或更新版本**和已加入 PATH 的 Git。

Windows 双击 **`Start-MeGit.cmd`**。首次安装依赖、构建，之后在浏览器打开 **http://127.0.0.1:4317**；关闭终端或按 Ctrl+C 停止服务。再次启动会打开已有 MeGit。数据只保存在本机。

也可以在本目录运行：

```powershell
npm ci
npm run build
npm start
```

开发前端和后端时运行 `npm run dev`，仍从 4317 访问完整应用。不要单独运行 Vite。更换端口可设置 `MEGIT_PORT`；更换数据目录可设置 `MEGIT_DATA_DIR`。开发模式另用 `MEGIT_PORT + 10` 的本机端口提供热更新。

## 使用工作流

1. 点击“添加仓库”，填写已有本机仓库的完整路径。子目录会被规范化为仓库根目录。显示名称可以自行修改。
2. 拖动节点调整位置；滚轮平移、Ctrl＋滚轮缩放，左下角提供缩放和适应画布。仅保存画布视角时，连线上的待推送和待拉取按钮保持可用。节点获得键盘焦点后可用方向键移动，Enter 打开详情。
3. 节点四边都有方形输出点与圆形输入点。将来源输出点拖到目标输入点，或点击“建立关系”。选中关系后，左上角副工具栏的编辑按钮可打开弹窗，修改名称、引用、连线样式和连接方向。
4. 从左侧打开的工作流会加入中间顶部的标签栏，可同时打开多个并点击标签切换。名称左侧的「i」查看说明与统计，右侧的关闭按钮只关闭标签，不删除工作流。关闭当前标签会切到相邻标签，关闭最后一个可从空区或左侧重新打开。单击卡片头像或留白可选中并突出上下游路径；点击仓库名称，或聚焦卡片后按 Enter，可打开分支树。点选枝梢查看对应开发线，点击关系连线查看真实比较结果与依据。
5. 点击“仓库分组”，命名并勾选成员。拖动分组标题整体移动，方向键也可移动整组；折叠时保留跨组关系，展开恢复成员位置。选中组后可从副工具栏打开编辑弹窗，左侧分组入口也能查看成员。将仓库移入另一组会自动移出原组；解散保留仓库、坐标与关系。
6. 右侧的仓库 Git 功能与关系比较横向并排，每列最小 320px，当前详情的底栏整块填深色。空间不足时，用底栏同一行两端的深色箭头按钮浏览；再次点击仓库或关系也可定位已打开的列。各列底栏标题单行显示，悬停或聚焦可查看全名；每列可单独关闭。详情区域和分支图隐藏滚动条，仍可滚动或拖动分支图。切回工作流时恢复未关闭的 Git 详情。工作流、分组与说明的编辑在画布弹窗中完成。
7. 在左侧「我的工作流」新建或打开工作流，当前工作流以深色卡片标出。同一个仓库可出现在不同工作流中。侧栏底部右侧的双箭头可收起或展开导航；桌面会记住折叠状态，窄屏通过应用左边缘的菜单按钮打开抽屉。画布右上角的「工作流设置」统一编辑名称和说明，也可在确认后移除当前工作流。移除不会删除本机仓库，最后一个工作流不能移除。全局选项仍在侧栏的「软件设置」；保存状态位于底部状态栏。

节点、说明、分组、连线样式、连接点、引用、布局锁定、视角与位置自动保存到 **`.megit/workspace.json`**。多个页面同时改布局会检测过期版本并保留现有文件；发生冲突时按提示刷新。移除节点或工作流不删除仓库。

工作流上的关系胶囊用底色区分状态：已整合和同步为绿，待整合和目标落后为橙，目标领先为青蓝，双方分叉为淡红，无法判断为灰，开发依赖和交付关系为蓝灰。点击胶囊仍可打开关系详情。

在「审阅并合并」面板中，可点「AI 审阅并生成提交消息」一次获取变更摘要、风险、建议检查项和合并提交消息草稿。预览阶段审阅来源改动，准备后审阅实际暂存差异与冲突路径。合并就绪时可手动采用或编辑草稿；它不会自动覆盖原有消息或提交。只有确认后才会把审阅内容发送到「软件设置 → AI 服务」配置的服务。

两个本地仓库的分支都在开发时，可编辑代码整合连线，单独勾选「允许从这条连线审阅并合并」。在连线旁先查看双方独有提交和来源改动；点「准备合并」才更新目标工作区和暂存区，不移动目标分支。出现冲突时可关闭窗口，到目标工作区解决并暂存，再重新打开连线检查实际差异并提交。取消合并可能丢弃本次合并及其冲突解决改动；关闭窗口不会取消。不需要 GitHub，不修改来源，也不会自动提交或推送。

「代码整合」连线匹配当前检出的本地分支和其上游卡片时，可执行的「推送」在胶囊右侧默认显示为蓝色，「拉取」在左侧默认显示为绿色；没有待同步提交的方向只在悬停或键盘聚焦时显示灰色图标，不能执行，触屏保留灰色图标。确认面板使用相同图标和颜色。两个独立本地仓库默认只比较；编辑关系，勾选「允许从这条连线快进整合」后，可用「整合到目标」把来源提交带到当前检出的目标分支。请继承卡片分支、跟随 HEAD，或填写完整分支引用。操作前会显示方向并请求确认，不会自动暂存、提交、修改远端配置或强推；分叉时请查看详情。上游胶囊状态以本机的上次获取记录为准。

关系详情以卡片显示来源和目标，窄面板上下、宽面板左右排列。本地分支 `refs/heads/main` 简写为 `main`，完整名称在提示中。卡片不再显示最新提交摘要；整合关系始终显示总结提示栏：已整合为绿色、待整合为警告色、无法核对保留原因，比较依据按需展开，显示来源／目标最新提交，并在图中高亮对应胶囊；收起恢复。总结问号靠右。提交图的来源与一般共同版本位于左侧，目标位于右侧；目标停在共同版本时，该提交也在目标列显示，宽面板各列与上方对应仓库卡片中心对齐。点击提交胶囊，在附近浮层查看说明、完整编号、作者、时间及共同版本／首次包含等位置，Escape 或外点收起；不再重复平铺提交列表。代码整合对比图只连接真实提交父子：已整合可查看来源最新提交及目标主线首次包含它的提交；关系图从最近共同版本开始，仅展示双方此后的开发，并可继续加载。例如 C→D 与 C→M→T 只显示 C、D、M、T，不展开 M 的更早侧线历史。局部图范围与完整待整合数量分别计算。最近共同祖先不一定是上次合并；快进可能没有新合并提交，挑选／压缩合并需另外核对内容。目标专属提交不会增加来源待整合数量。

点击分支名称可在地图底部查看仓库与分支，HEAD 和比较树干标记紧随分支名。「工作区」显示改动、暂存和提交，「分支同步」在单独的浅底区显示跟踪关系与推拉。窄面板只显示暂存操作图标；点击提交消息左侧图标可展开多行编辑，按 Escape 返回。地图右上角的「远端管理」可添加远端或获取全部远端；添加只登记地址，获取只更新本机的远端记录。左侧按钮直接查看工作区改动。缩小、放大和居中位于地图左下角。分支标签右侧并排显示「图上比较」和「查看提交差异」：前者与树干比较，关闭浮层即清除高亮；后者打开该分支最新提交的差异，无需先打开详情。两者只读取本机历史，不会切换分支或执行同步。

在「远端管理」中，每个远端的卡片显示读取状态，并可单独「检查读取访问」；「获取全部远端」和「添加远端」始终在底部。读取检查不获取分支，也不验证推送权限；公开仓库可在未登录时读取。GitHub.com HTTPS 远端另有「登录 GitHub」，确认后由本机 Git Credential Manager 打开浏览器授权，凭据由它管理。登录不会自动重查或获取；SSH 与本机远端仍使用原来的访问方式，MeGit 不自动切换。添加远端时不要在地址中嵌入账号、密码或令牌。

在当前本地分支的「分支同步」区，未设置跟踪时可用「发布分支」把已有提交发布为新远端分支。目标同名分支已存在时不会更新它，发布成功也不会自动设置跟踪。「设置跟踪」只关联明确选中的、已获取的远端分支；已有有效上游时才显示待推送／待拉取，以及推送和拉取入口。上游失效时不会切换目标，也不会在普通推送中重建已删除的分支。

分支详情用细线区分「工作区」和「远端」。从工作区标题右侧可查看改动；从远端标题右侧可展开查看仓库配置的所有远端名称。待推送／待拉取数量只对应当前显示的跟踪分支；「获取」更新所有已配置远端的引用。浏览远端名称不联网。

分支详情会为可识别的 GitHub 远端显示外链图标，点击后在新标签页打开对应分支。远端若是本机目录，文件夹图标会显示可复制的仓库路径，可粘贴到资源管理器地址栏打开。两种入口都不执行 Git 同步，也不会切换分支；无法识别的地址不显示入口。

工作流标签栏横跨画布与右侧详情，仓库和关系详情的操作栏位于各自面板底部。点击「我的工作流」标题行里「+」左边的「隐藏工作流面板」，可暂时隐藏画布并让右侧详情填满工作区，不关闭任何标签；再次点击即可显示画布。

切换工作流时恢复该工作流上次打开的 Git 详情、顺序、当前项和宽度。刷新页面还会恢复工作流标签及顺序、正在查看的工作流、画布显隐、选中分支、比较视角、展开与缩放、滚动位置，以及工作区／历史／差异窗口、提交说明草稿和 Git 课堂进度及位置。浏览记录保存在当前浏览器标签页的 `sessionStorage`（`megit.view-state`），多个浏览器标签页互不覆盖；关闭浏览器标签页或清除该来源的浏览数据后可能清空。已删除的对象会清理，刷新不重放 Git 操作或确认表单。主题、语言和导航折叠继续使用浏览器偏好，工作流内容继续使用工作区文件。

折叠后的左栏保留「我的工作流」和「工作流中的仓库」图标，点击后在右侧浮动显示对应列表。选择工作流可切换工作流，选择仓库可定位并打开 Git 详情；左栏保持折叠。仓库列表保留头像、分组与状态，空工作流显示空态；工作流列表可直接新建工作流。两个列表互斥，点击入口可收起，外点、焦点离开或 Escape 关闭；入口获得键盘焦点后按右方向键或下方向键可进入列表。长列表在面板内部滚动，窄屏仍使用导航抽屉。

画布用蓝系点阵底色，右侧详情及分支树与左侧导航同色，不使用点阵。画布与详情区之间没有常驻分割线。画布显示时，拖动详情区域的左边界可调整当前工作流的详情宽度，最大为窗口的 2/3。边界获得键盘焦点后，左右方向键微调，按住 Shift 加大步长，Home 最窄、End 最宽；双击恢复默认 365px。每个详情独立上下滚动；打开、关闭或调宽不改变画布视角。画布右上角的“工作流设置”集中编辑名称和说明，也可移除当前工作流。

选中元素后，左上角副工具栏显示红色“移除所选元素”垃圾桶按钮，支持单项与多选；右侧 Git 区域不显示移除底栏。仓库节点、关系、分组和说明的移除可在本次页面会话中撤销；解散分组保留成员仓库与关系。“工作流设置”中的“移除工作流”需要再次确认，会移除该流程的全部内容且无法撤销，本机仓库、Git 历史与其他工作流保留。确认窗口默认选中“取消”；最后一个工作流不提供移除入口。Git 分支删除沿用单独确认和安全合并检查。

### 画布工具

选中连线，在左上角副工具栏点击“编辑连线路线”：拖动线段中间的短柄平移走向，拖动圆点移动折点；双击短柄添加折点，双击圆点或聚焦后按 Delete 删除该点。方向键微调，Shift 加大步长，Escape 或窗口失焦取消本次拖动。松手后自动保存，一次拖动可一步撤销；“恢复自动路线”清除自定义路线。流程线和仓库关系均支持，端点与 Git 引用保持；锁定布局、平移模式和折叠组投影时需先解锁、回到选择模式或展开分组。刷新与导出保留路线，每条线最多 20 个折点。

连线路线编辑共用默认开启的自动吸附：拖动折点靠近相邻点时横向或纵向对齐，拖动水平／垂直线段沿法向吸附到本条路线的固定点。参考线即时显示；按住 Alt 临时自由调整，松开立即恢复吸附。磁铁开关、屏幕距离与工作流节点一致，方向键保持自由微调。

仓库卡片每边默认只有一个居中的连接点，可接入也可引出。同一边的多条同向连线共用该点；同时存在入线和出线时，才自动分成两个对称的输入／输出点，删除连线后自动合回。Git 关系使用“状态桥”：中间粗线与两侧细线沿同一路径绘制，圆形起点表示来源，汇入端口表示目标，中央显示已整合／待整合／待核对；悬停或键盘聚焦查看关系原名和含义，点击查看详情。普通维护流程继续用箭头表示执行顺序。未指定连接边的自动路线适应横向、纵向与斜向布局；已指定端口与手动折点保留。两类线共同决定可见连接点，刷新、撤销和 SVG／PNG 导出保持方向。 画布缩放低于 70% 时以固定屏幕宽度的单线显示，放大后恢复三线；导出始终保留三线。

选中仓库卡片后，用工具栏的「绑定卡片分支」选择跟随 HEAD、本地分支或远端跟踪分支。要并排展示同一个仓库的多个分支，再次「添加仓库」，从已登记仓库选择该仓库，再选择另一分支。例如用代码整合关系连接 MeWiki 的 origin/main 与 main，工作流会显示目标领先、落后、分叉或一致。远端跟踪分支反映上次获取到的状态，并非实时远端。分支地图默认以绑定分支为树干；卡片只有跟随 HEAD 或绑定当前检出的本地分支才显示暂存和提交区。

“添加流程步骤”提供处理、判断、开始和结束形状；图上仅显示名称与摘要，完整命令和通过条件放在详情。拖动步骤连接点可建立独立的有向流程线，填写“通过”“有冲突”等条件；点线上的条件编辑端点和路由。流程线表达顺序，不计算或冒充 Git 整合、检查和部署结果。步骤及连线支持保存、删除清理、撤销、聚焦与 SVG／PNG 导出。已有普通说明保持原样，已连线的步骤改为普通说明仍保留连接。

阅读完整流程图时，从“开始”沿箭头经过判断分支前进；失败箭头返回对应修复步骤。左下角“适应画布”查看全图，再放大或平移阅读具体阶段。仓库节点继续显示真实状态，Git 整合线与维护流程线分别记录。

- 画布左上角的白底开关常驻显示“选择／平移”，当前模式以蓝底标出。鼠标靠近或键盘聚焦时显示其余编辑工具；按住鼠标拖动画布时不会触发展开，松手后恢复。触屏可直接使用。选择模式下在空白处（包括展开分组内的留白）按住鼠标左键拖框，触及的卡片会选中；框选不会选中关联线或展开的分组外框。Shift／Ctrl 点选多项，Ctrl+A 选择当前可见内容；多选后用方向键或拖动选择框一起移动。点击分组标题可选中整个分组，与成员同时选中也只移动一次。
- 多选后显示排列入口，可对齐边缘、居中或等间距分布；分组保留内部相对位置。所选仓库也可直接创建分组。
- 拖动卡片、分组或多选项时，按住 **Shift** 会按当前主要拖动方向锁为横移或纵移，松开 Shift 即恢复自由移动。自动吸附仅沿可移动的方向生效；按住 **Alt** 可暂时跳过吸附，不解除锁轴。
- 磁铁按钮控制“自动吸附”，默认开启。拖动仓库、说明或分组时，靠近周围元素的边缘、中心线或相等间距会精确对齐并显示参考线；多选按整体外框处理。松手后保存当前预览位置，一次拖动对应一步撤销。开关在此浏览器记住；方向键微调不受吸附影响。拖动中按 Escape、加入第二触点或窗口失焦会取消本次移动，恢复起点并清除参考线，不产生撤销记录。
- “锁定布局”固定现有节点位置，解锁后可移动、排列和撤销；名称、说明和 Git 查看仍可使用。左下角“锁定缩放”独立固定比例，仍允许平移。布局锁定保存到工作流，工具模式和缩放锁定按当前标签页和工作流记住，刷新后恢复。
- 撤销／重做只作用当前工作流的内容编辑，快捷键为 Ctrl+Z、Ctrl+Shift+Z／Ctrl+Y；每个工作流保留最近 50 次，刷新页面后清空。输入框中保留浏览器原生文本撤销。视角、锁定、仓库登记与真实 Git 操作不参与历史。
- “添加说明”创建带虚线边框的人工说明并打开编辑弹窗。点击说明本体选择，点击详情箭头、按 Enter 或使用副工具栏编辑标题与正文。它没有 Git 端口，也不参与提交比较；说明文字由你维护。
- 选中节点或分组后可聚焦所选内容，或聚焦可达的上下游；“退出聚焦”恢复完整工作流。过滤不改仓库、分组与真实连线；新增说明或从导航打开视图之外的仓库会退出聚焦。
- “导出工作流”下载独立 SVG 或 PNG，按当前主题和可见范围导出节点、分组、连线及显示的状态。工具栏、选择框和详情中的路径等信息不导出；自行写进说明或名称的文字仍按显示内容保留。SVG 保持矢量文字和路径，PNG 在大型工作流上会限制尺寸以控制内存。

### 三种关系

| 类型     | 含义与判断                                                                        |
| -------- | --------------------------------------------------------------------------------- |
| 代码整合 | 检查目标引用是否包含来源引用的提交，默认比较两边的 HEAD；可改为分支名或提交 SHA。 |
| 开发依赖 | 由用户定义的开发顺序或项目依赖，不自动推断代码同步。                              |
| 交付关系 | 由用户定义的构建或交付方向；首版尚未接入 CI、发布或线上状态。                     |

“已包含”表示来源提交是目标提交的祖先；“待整合 N”表示目标缺少来源的 N 个提交。目标尚未获取来源对象、没有共同历史或仓库不可用时显示“待核对”。重新提交、squash 和 cherry-pick 可能保留相同行为却没有相同祖先，需人工核对。连线不执行 merge、复制或部署。

提示「目标仓库尚未获取来源提交」时，在目标仓库的分支地图打开「远端管理」，找到来源远端并点击「获取」。如果还没配置，可把来源仓库的本机路径添加为远端，不需要 GitHub。获取只补齐比较所需的提交和远端引用，不会把改动合入目标分支。检查读取访问和适用的 GitHub 登录都在各远端卡片的齿轮里。

## 仓库查看与操作

- 点击仓库详情标题左侧的图标可设置“仓库头像”：在仓库目录中浏览并预览项目 Logo，点击“使用此头像”保存，也可恢复默认图标。支持 SVG、PNG、JPEG、WebP、GIF、ICO，最大 1 MiB；只保存仓库内相对路径，不修改文件或 Git 历史。同一仓库在所有工作流的节点、导航、仓库索引、分组与详情中共用头像；图片丢失时回退默认图标，工作流仍可编辑。导出工作流会内嵌头像，不携带图片路径。
- 每 15 秒检查当前工作流的本地工作区，回到页面时也刷新。右上角“刷新状态”只检查本地。
- 待推送／待拉取来自**本地缓存的远端引用**；“刷新状态”只读取本机，“获取”才联网更新。分支树工具菜单也提供“获取”，会同步清理远端已删除分支的本机记录（`git fetch --all --prune --no-recurse-submodules`）；过期远端标签消失，本地分支和已合并历史仍保留。没有跟踪分支或计数未知时显示 `—`，不会显示虚假的零。
- 仓库详情默认显示分支生长树：下方是较早提交，上方是较新提交；比较分支为树干，线宽为其他树枝的三倍，绿色合流线表示真实合并关系，连线沿独立直轨道延伸，仅在连接点附近用逐渐弯起并收直的平滑弯道接入；源分支继续开发时避开后续提交，实心正方形标记当前代码位置，其他提交为圆点。同点引用共用提交节点，不同历史保持独立。
- 分支地图左下角提供缩放和居中，右上角保留帮助与工具入口，不显示常驻树干导航行。比较树干、真实合流、HEAD 方形及点选方法统一在「?」帮助中查看，各详情列底部不重复显示图例或教学提示；帮助支持悬停、键盘聚焦、点击固定及 Escape 收起。从“分支树工具 → 更换比较树干”选择并应用视角，取消保留原视角；点击枝梢标签右侧的“图上比较”图标，分别查看两边独有的提交与共同历史关系。关闭浮层即结束比较并清除地图高亮。浏览和比较不切换代码；计数核对完整本机历史，图中只突出已加载的独有提交，无法判断的原因直接显示。
- 圆角矩形是分支名称标签，标记该分支当前指向的最新提交，多个名称可以指向同一个提交。悬停或聚焦查看完整名称与所指提交的具体事件，点击只打开分支详情。选中时明亮主题使用品牌深蓝底白字，暗黑主题使用色卡浅色底深蓝字，图标与 HEAD 同步反色，不显示额外选中外框；当前代码位置的实心方形为 18px。+X 表示该段连线折叠了 X 个连续提交，不是文件数、未推送数或待合并数；可悬停、聚焦或点击阅读说明，在「分支树工具 → 展开连续提交」逐个查看。
- 点击地图中的分支标签、连线和提交，或打开／关闭详情时保持当前视角；刷新数据不主动重新居中，可点击“居中查看树干”手动定位。地图默认滚轮上下滚动，Ctrl＋滚轮或触控板双指捏合缩放，范围 50%–200%，围绕鼠标位置缩放，网页和画布视角保持不变。Shift＋滚轮左右移动，按住鼠标右键拖动可自由平移；水平滚动和滚动条仍可浏览内容；按钮仍可缩放和居中。工具菜单可查找分支、显示缓存的远端分支和展开连续提交，矮窗口中菜单可内部滚动。默认读取 120 条历史，可逐步增至 600；虚线标出尚未加载的父提交，压缩保留真实分叉和合流。
- 点选枝梢后显示当前／占用状态、独立跟踪与同步状态及创建、切换、安全删除等适用操作。点击分支详情的「i」查看完整引用、SHA 与检出目录；只将当前工作目录的修改关联到当前分支。
- “查看工作区改动”和“查看提交历史”按需打开窗口，不保留常驻文件或标签导航。工作区标题栏依次显示“工作区”、仓库图标、仓库名称和当前分支。工作区支持文本差异、暂存、取消暂存和提交；各仓库的提交草稿在关闭窗口后仍保留。历史每页 40 条，可继续加载；合并提交的差异对照第一父提交。
- 点击地图中的提交圆点，会打开提交操作菜单，可查看该次差异、从该提交新建分支或复制完整编号。新建窗口锁定所点版本，填写名称并确认后才创建，默认保留当前分支与未提交修改；勾选“创建后切换”需先处理修改。提交操作不随地图缩放，滚动或缩放地图时收起。复制失败时提供完整编号供手动复制。
- 点选远端枝梢仍可创建本地跟踪分支，此步骤不联网。创建 worktree 和跨分支写入式合并尚未接入。
- 切换和删除前展示仓库、目标分支与提交供确认。切换要求没有未提交修改；可能覆盖被忽略文件时也会拒绝。删除只允许已并入当前提交、非当前且未被其他工作树占用的本地分支。
- 分支、提交或起点在确认后变化时会拒绝操作，可从弹窗刷新后重试。进行中的合并、变基等 Git 操作需要先处理；空仓库需先首次提交。分支动作不进入工作流撤销历史。
- 有待拉取提交时，「拉取」显示浅青绿。有待推送提交时，「推送」显示主题蓝。拉取和推送均需确认同步方向，获取可直接执行。拉取只允许**干净工作区上的 fast-forward**，推送使用当前分支既有跟踪远端，不强推。远端认证使用电脑已有的 Git 凭据配置，需要交互认证时先在终端完成。
- 没有丢弃修改、重置仓库、强推、自动整合和自动发布操作。

Git 操作使用本机现有配置，用户主动提交、推送或切换分支可能执行该仓库原有的 Git hooks。请只登记自己信任的仓库。

### 本地服务（Windows）

配置保存后，圆形服务按钮半嵌在当前 HEAD 仓库卡片靠右的上沿。启动用绿底，停止用红底；卡片选中时，按钮也显示同色的蓝色细边。悬停只显示提示，不改变按钮外观或大小。服务运行时，计时显示在卡片上沿上方、停止按钮左侧，不改变卡片本体尺寸；不足一天只显示 `02:03:04`，满一天才显示天数，如 `01天02:03:04`。时长每秒更新，刷新页面不会归零，重启服务才会重新计时。端口冲突等错误显示在卡片内，重启、完整日志和配置仍在「仓库详情 → 本地服务」。

为仓库编写启动入口时，参阅 [本地服务脚本规范](docs/LOCAL_SERVICE_SCRIPTS.zh-CN.md)，内含可复制的 npm 和 PowerShell 示例。

配置后，顶部显示运行状态和启动入口，正文直接显示终端输出，底部右侧提供启动、停止和重启操作。服务运行且配置了 TCP 端口时，点击底栏左侧的「打开服务」，即可在新标签页打开 `http://127.0.0.1:<端口>`。

返回工作流后，每个活动服务在中间面板底栏左侧各有一个终端标签，点击即可直接打开对应仓库的终端；保存与检查等信息收在底栏右侧的「状态信息」中。

打开仓库详情，点击标题栏的「本地服务」。选择仓库内的工作目录（`.` 是根目录），输入 `package.json` 中已有的脚本名（例如 `dev`），或填入相对于该工作目录的 `.ps1` 文件路径。只确认你已经审核的入口及其依赖代码；保存不会启动项目，也不需要另外写停止脚本。npm 入口不运行同名的 `pre` / `post` 生命周期脚本；需要准备工作时可以写进启动入口。PowerShell 使用本机执行策略。

填写实际 TCP 端口后，MeGit 会等待本次启动的进程组监听该端口；不会把别的进程误当成服务，也不会按端口结束它。不同项目占用同一端口时，先在原工具里停止占用者，或在项目和 MeGit 里同时更换端口。「打开服务」用于通过 `127.0.0.1` 访问的 HTTP 服务；不要把开发服务绑定到外网。不填端口时，只跟踪进程组，不判断应用是否就绪。

按工作树保存一份本机配置；关闭窗口、刷新网页和切换工作流不会停止服务。停止和重启会结束本次启动的进程组（不保证应用有时间保存状态）；MeGit 后端退出时也会结束其管理的服务。请使用持续运行的前台启动脚本，不用于 Windows 服务或需要管理员权限的应用。分支、提交或入口变化时需要重新审核；运行中的服务请先停止，再编辑或重新保存配置。最近输出仅保存在本次 MeGit 会话中，项目代码仍可能把敏感信息写入日志。

## 外观与语言

默认使用暗黑主题和简体中文。点击底部调色板“偏好设置”（窄屏也可从画布右侧打开），可切换主题和界面语言，立即生效并保存在当前浏览器。底部齿轮单独打开“软件设置”，窄屏可在导航抽屉底部找到。

在「软件设置 → 网络代理」填写可信代理的 HTTP/HTTPS 地址（例如 `http://127.0.0.1:7890`），点击「测试代理」检查能否经它访问 GitHub；测试不保存设置。勾选启用并保存后，后续 Git HTTP/HTTPS 同步、远端读取检查、GitHub 登录的后台请求和远程 AI 请求会使用该代理，不会在失败时改用直连。回环地址和本机仓库不经代理；浏览器打开的网页由浏览器自身设置控制。外网 SSH 不使用这项代理，启用代理时遇到外网 SSH 远端会提示不支持。MeGit 不更改系统代理或 Git 配置。

语言切换覆盖界面、提示、错误、无障碍名称和时间。仓库与工作流名称、自定义关系名、分支和提交内容保持原样；空的关系名称使用当前语言的默认名称。浏览器无法保存偏好时会提示，现有工作流和仓库配置不受影响。

后续开发同时支持两套主题与多语言，具体流程见[主题与国际化开发标准](docs/THEME_I18N.md)。

产品标志使用本地 SVG：启动页和帮助窗口显示完整 Logo；左侧导航展开时显示小尺寸完整 Logo，折叠为 Ribbon 后显示同等大小的独立图形。Logo 所在顶部行高 44px，右下方为版本徽标，右侧为“使用帮助”；折叠时帮助入口保留在 Ribbon 底部。底部不显示本地服务行。导航 Logo 使用透明背景，直接融入栏位底色；浏览器图标也使用独立图形。名称随主题调整为浅色或深蓝色，图形保留品牌配色，暗黑主题增加柔白细轮廓以改善辨识度；源文件和使用说明见 [品牌资源](public/brand/README.md)。

后续产品配色统一使用 Logo 提取的深蓝、亮青和绿色及其配套色阶，明暗主题均已接入。[配色规范](docs/COLOR_GUIDELINES.md)与[色卡](public/brand/color-palette.html)说明颜色用途、对比度和功能扩展边界。

尺寸、排版、组件、表单反馈与画布交互统一遵循[产品设计规范](docs/DESIGN_SYSTEM.md)。启动后访问 [真实组件示例](http://127.0.0.1:4317/design-system)，可检查加载、禁用、错误焦点、长名称与空态，并切换明暗和中英文；此页面不读写工作区。

自动保存发生连接或传输失败时，页面会保留未保存修改，提供“重试保存”；成功前请保持页面打开。版本冲突会停止后续写入并持续显示原因，不自动覆盖其他页面的数据。添加仓库等异步表单会在提交中锁定重复操作，失败后将错误关联到对应字段。

展开或收起导航、打开或关闭详情面板时会保留当前画布视角；需要重新定位全部内容时，使用“适应画布”。左下角「隐藏流程图」可暂时隐藏所有流程步骤与流程线，保留仓库卡片、仓库关系、分组和普通说明；再次点击恢复，不修改工作流内容。

画布左下角是竖排视图工具栏。点击“流程缩略图”图标可显示或隐藏右侧的小地图；每个工作流分别记住开关状态。小地图支持拖动平移，未锁定缩放时也可用滚轮缩放。

界面遵循[简洁与渐进式披露原则](docs/UI_GUIDELINES.md)：常用动作留在单行工具栏，悬停或聚焦图标查看说明，Escape 收起。关系详情的“比较依据”按需展开；无法核对的原因直接显示。更完整的工作流操作说明放在帮助中。

点击按钮后提示会立即收起，关闭弹窗返回原按钮时不会再次弹出。导出和排列菜单支持点击外部、焦点离开或 Escape 关闭；键盘可用方向键浏览，Tab 自然离开。触摸操作不依赖悬停；窄屏弹窗与导航按层级关闭。

图标提示统一显示在浏览器顶层，跨越导航、画布和滚动容器的边界，并在窗口边缘自动避让；弹窗内部的提示也保持完整可见。

中间和右侧的顶部标题栏、底部状态栏与左侧导航同色。仓库详情标题栏采用与底部状态栏相同的紧凑高度，桌面单行 29px；长名称自动换行，触屏保留较大的点击目标。关闭按钮左侧提供「i」仓库信息入口，点击后按需查看本机路径、完整提交编号（HEAD）、跟踪分支、远端名称与检查／获取时间。默认展示分支树，点选分支后显示其修改或同步状态；无法访问仓库、冲突和进行中的 Git 操作保持可见。

Git 状态和操作提供面向初学者的详细说明：先解释术语，再说明操作会影响哪些内容。工作区、暂存、提交、分支、关系比较与差异窗口的问号支持悬停、键盘聚焦或点击固定查看；详细提示允许移入阅读，Escape 先收起提示，再关闭信息浮层或窗口。查看帮助不会执行 Git 操作，提交草稿会保留。

### Git 命令提示

鼠标停留约 500ms 后显示提示，键盘聚焦立即显示。Git 操作的提示按当前分支、提交编号、文件路径和输入正文展示主要命令，使用 PowerShell 字面参数写法；需要确认的入口会说明确认阶段，创建窗口的确认按钮跟随输入更新命令。推送目标读取真实跟踪配置，不由显示名称猜测。复制、筛选、缩放等纯界面动作不生成 Git 命令。提示只展示文字，不会执行操作；实际执行仍保留状态及安全校验。

提交点与分支名称提示展示各自的提交说明、作者、时间、父提交及引用，区分初始、普通与合并提交；浅克隆的空父历史标为无法确认初始提交的边界。通用图例、HEAD、折叠数量和提交操作方法统一查看分支地图右上角「?」。

流程步骤使用透明轮廓，与仓库卡片区分。选中后通过左上角副工具栏编辑，或聚焦节点后按 Enter 查看详情。点击流程线选中，拖动任一端圆点到其他步骤／仓库的连接点，可更换连接对象或方向；点击条件标签只编辑文字。拖到空白处、自连接或重复连接保留原线，成功后支持撤销／重做和自动保存。折叠分组需先展开；平移模式和布局锁定时无法改线。导出 SVG／PNG 同步保留透明流程形状。

工作区标题栏下方常显单行分支同步区：左侧是待推送／待拉取，跟踪状态居中，获取／拉取／推送靠右；窄窗口用图标保留操作，较长的跟踪状态可横向滚动。中间左栏是工作区修改、右栏是已暂存，分别滚动；计数只在各自标题中显示，「全部暂存」「全部取消」分别位于对应标题栏右侧。窄窗口上下排列。提交说明和提交按钮固定在底部，未暂存时也可先写说明。分支地图中当前 HEAD 的详情卡片复用同一提交区，无需打开文件列表即可暂存、取消暂存与提交。两个入口共用按仓库保存的草稿，只有提交成功后清空；提交仅保存已暂存内容，不自动暂存剩余改动，也不推送。冲突时明确提示并禁用提交，文件差异仍通过“查看工作区改动”按需查看。

点击分支树的 `+X` 提交数量可打开局部历史浮层，像放大镜一样逐个点选被收起的提交。浮层是无标题的竖长气泡，尖嘴指向 `+X`，头尾用延伸线表示与外部历史相连。历史独立滚动、从下往上生长。与主地图一致，点提交标记便可在菜单中查看差异、新建分支或复制编号。Escape、再次点击 `+X` 或点击外部收起，主地图位置与缩放不变；右上角工具仍可展开全图连续提交。

分支树提交点被选中时保持原来的形状，圆点放大为两倍圆点，HEAD 方块放大为两倍方块；关闭提交操作后恢复，点击区域始终保持可操作大小。

画布连接点默认隐藏，鼠标移到卡片或连接点、键盘聚焦卡片时出现；触屏保留可见连接点。流程线选中后，两端原有连接点保持原形放大两倍，仍可从端点拖动重连。取消选择、锁定布局或切换平移后恢复原尺寸。

## MeGit AI 助手

悬浮入口、聊天标题、欢迎页和助手回复使用同一款 MeGit 品牌头像。悬浮入口无描边，悬停时底色和头像保持不变；拖动时显示完整胶囊，松手后恢复贴边外观。

点击屏幕边缘的「AI 助手」悬浮球打开独立聊天窗口；窗口打开时收起悬浮球，关闭后恢复原位置，可同时引用最多20个已登记仓库，不占右侧Git详情。悬浮球支持拖动并吸附左右边缘，方向键移动入口；窗口标题可拖动，四边和四角均可调整大小，聚焦边缘后用方向键微调、Shift加速。窗口可贴齐页面四边或铺满视口，没有保护间距，窄屏保留实际调节能力。输入框聚焦不显示外围蓝框；明亮模式标题栏使用品牌深蓝背景与浅色图标。顶部新建、切换和删除对话，底部选择引用仓库并输入目标，Enter发送、Shift+Enter换行。当前标签页会记住聊天、输入草稿、引用范围、悬浮球、窗口与滚动位置，刷新不重放操作。

可直接要求「检查这些仓库的分支状态」「暂存全部改动，用指定说明提交」「把已有提交推送到跟踪分支」。助手先回复并生成按仓库分组的计划，显示实际分支、可编辑提交说明、目标分支和可展开的命令；核对后点「确认执行计划」。首版支持获取、暂存全部、提交及推送到现有跟踪分支；缺少远端或跟踪时，先在仓库详情完成配置。获取需作为独立计划，之后重新检查状态再继续。不会执行任意终端命令、强推、自动合并或自动发布新分支。

助手也能解读和修改当前流程图，无需先登记仓库。点击「解读当前流程」「补充测试流程」「整理流程布局」会明确引用当前流程图，也可在引用选择中自行勾选。可以要求「增加测试失败后返回修复的分支」「把发布步骤改成判断节点」「移除旧步骤并重连」「按流程方向整理布局」。支持步骤的增删改、流程线的增删和重连、元素移动、横向或纵向整理、流程名称和说明修改；仓库分组在整理时整体移动并保持内部位置。模型先给出修改清单、具体字段与图形预览，点击「确认应用到工作流」才整批应用并自动保存，可一步撤销。工作流变化、布局锁定、未完成保存或计划过期时禁止应用；刷新恢复审阅状态，已应用或放弃的计划不重放。此入口不执行步骤里写的命令，也不更改 Git 关系或仓库绑定；Git 操作与流程修改分开计划。

想一次完成暂存、生成说明、提交和推送，可引用目标仓库，点「暂存、提交并推送」填入草稿，或直接在聊天中提出。打开「发送范围与能力」，勾选「仅允许下一条消息发送拟提交差异」再发送。差异可能包含未暂存修改和新文件，请先确认内容适合发送给已配置的 AI 服务。助手预览拟暂存结果，按仓库生成可编辑的提交说明；核对改动范围、分支和推送目标后，点击「确认执行计划」才执行。已全部暂存时不重复暂存；使用 Git 内容过滤器的文件请先手动暂存。直接提供提交说明不需要授权发送拟提交差异。

默认只发送所选仓库名称、分支、状态和最近对话及相关执行结果；流程图引用默认关闭，选择后发送当前流程的名称、说明、步骤全文、位置、分组与连线，包括用户填写的内容（最多200,000字符），可点击引用旁的移除按钮取消。「发送范围与能力」也可单独允许附加已暂存差异。每条聊天请求发送的两类差异合计最多48,000字符，含文件名和代码；不自动附加仓库登记路径或密钥。

每个计划15分钟内有效且只能执行一次。执行前后核对文件、暂存区、分支和配置；变化或失败会停止本仓库后续步骤，其他仓库继续报告各自结果。「停止后续操作」会等待当前Git操作结束，不回滚已完成操作。执行状态可在刷新后继续查询；本地服务重启后旧计划失效，不能重放。对话最多12个，每个最多80条消息，可在历史中删除旧对话；删除对话不撤销Git操作。

点击引用行最左侧的按钮选择引用。输入框内部左下角依次是发送范围说明和能力范围；模型按钮在底栏右侧，发送／停止按钮嵌在输入框右下角的方形缺口内。点击模型按钮可打开「AI 快捷设置」，填写兼容 Chat Completions 的接口基地址（如服务商提供的 `/v1` 地址）、模型和 API Key，保存后可测试连接。「软件设置 → AI 服务」把连接参数与项目交付权限分组；AI 服务和网络代理的测试、保存按钮固定在表单底部。远程接口须使用 HTTPS，本机模型支持回环 HTTP；无需密钥的本机服务可留空。Windows 使用当前用户的系统凭据保护保存密钥，更换接口时须重新填写或明确清除旧密钥。MeGit Agent 内置，无需单独部署。

AI 聊天输入框左下角显示当前对话的能力范围。「默认范围」可读取已引用的仓库上下文，并读取、编辑已引用的工作流。要读写项目文件，先在「软件设置 → AI 服务」勾选「启用 AI 项目交付」并保存，再在聊天中仅引用一个仓库，点击左下角「默认范围 → 仓库读写」，无需重新选择仓库。「了解更多」显示本地路径、AI 接收端和文件读写规则。仍在原聊天框发送需求；普通问答和工作流编辑不受影响。更改仓库引用会恢复默认范围；新对话和页面刷新均不会继承读写授权。

授权后，发送消息时可能将筛选后的相对文件名和按需选取的文本发给 AI 服务；不会读取 `.env`、`.git`、忽略路径或链接到外部的文件。自动筛选不能保证识别所有机密。变更方案出现在聊天消息内，显示发过内容的文件及修改前后的文本，确认后才保存；只支持在现有目录内新建或修改文件，不删除、不执行，也不自动暂存、提交或推送。

例如输入「按 MeGit 的规范生成 MeWiki 本地启动脚本并配置」，可以审阅新建或修改的 `.ps1`、工作目录和端口。选择「仅保存文件」，或勾选信任后「保存文件并配置」。启动配置仅保存，不会启动项目。仓库、文件或 AI 配置变化时须重新生成，不会直接覆盖。

仓库解读仅发送所选仓库的状态计数和两个状态标记。流程图生成会发送输入的流程说明；它先显示节点和连线草稿，确认后才写入工作流，可用工作流撤销移除。AI 不运行 Git 写入、终端命令或推送。

仓库卡片左侧图标跨两行，右侧显示名称、当前分支及已修改／已暂存数量。底部可直接点击绿色「全部暂存」按钮，填写单行提交说明，再点提交图标；输入框左侧可展开多行编辑，关闭后保留草稿。仅提交暂存区，失败保留草稿。草稿与右侧详情共用，刷新后恢复；同一仓库操作期间各入口同步禁用。暂存后点击输入框右侧的 AI 图标，将已暂存差异（包含文件名及代码，最多 48,000 字符）发送到配置的 AI 服务，按当前界面语言生成单行说明。请先确认暂存内容适合发送；未暂存／未跟踪内容不会附加，二进制只包含差异标记。结果只填入草稿，可编辑后手动提交；生成失败、离开页面或暂存内容变化时不会覆盖原草稿。

仓库卡片分别常显「已修改 X」与「已暂存 Y」，包含零数量。已修改仅统计尚未暂存的工作区修改及新文件；同一文件暂存后继续修改时同时计入两项，说明通过悬停／键盘提示查看。两项使用彩色纯文字紧随分支名称，以 | 分隔；已修改为警告色，已暂存为成功色，不使用徽标边框／底色。仓库名称使用700粗体。
从左侧栏底部、偏好设置上方打开「仓库管理」，可登记现有本地 Git 仓库、编辑显示名称或更换头像。添加仓库时可设置「卡片显示名称」；已有卡片可选中后打开「绑定卡片分支」修改。名称仅作用于当前卡片，清空后使用仓库的登记名称，未自定义的仓库默认使用文件夹名称。登记不加入工作流，也不修改 Git 文件；使用卡片上的独立按钮打开已引用的工作流或加入当前工作流。

登记时可用 Windows 文件夹选择器；编辑时仓库路径只读，头像文件需位于仓库内。归档隐藏索引主列表和添加候选中的仓库，保留既有工作流，可在「归档」恢复。永久移除登记需要输入完整显示名称并勾选同意，仅清理 MeGit 登记及工作流引用，不删除磁盘文件或 Git 历史。
