# MeGit 配色规范

版本 1 · 2026-11-16。适用于 MeGit 后续页面、组件、白板、图表、宣传物料和桌面外壳。品牌色以已确认的 SVG 为准，不从带有压缩噪声的 JPG 重新取样。

[查看可交互色卡](../public/brand/color-palette.html) · [矢量色卡](../public/brand/megit-palette.svg) · [颜色数据](../public/brand/palette.json)

## 品牌原色

- **MeGit 深蓝 `#01357C`**：品牌主色，明亮主题的主要动作、链接及名称；Logo 深蓝渐变保留 `#063C84 → #003478`。
- **MeGit 绿 `#86D21F`**：品牌辅助、成功和已包含；Logo 绿色渐变保留 `#80CB19 → #86D21F`。
- **MeGit 亮青 `#00A9F3`**：交互强调、暗黑主题主要动作和焦点；Logo 渐变保留 `#00A9F3 → #00A1EE`，下节点为 `#0390E0`。
- **标志白 `#FFFFFF`**：Git 节点与连线、留白、明亮表面；它是标志图形的一部分，不是必须铺满的背景。

原色与渐变端点不得随主题改色。完整 Logo 的字形允许按现有规范在深蓝与浅色文字之间切换。

暗黑应用界面的图形允许叠加柔白细轮廓，以增强深蓝边界与深色背景的区分。语义 token `--brand-symbol-outline` 在暗黑为 `#E9EDF3CC`，明亮为 `#FFFFFF00`；导航实际尺寸约 0.5px。轮廓来自已有中性色，属于环境辅助，不改变原始品牌资源或为 Logo 增加底托。

## 色阶与中性色

深蓝、亮青与绿色各提供 11 档色阶。色阶以原色与白／黑的 sRGB 混合为基础，详见 `palette.json`；它们用于正文、按钮悬停、浅底、选择与差异底色。品牌视觉保持蓝、青、绿关系，避免自行加入紫色等装饰性主色。

中性色维持原有深灰工作台风格，分布于白、冷灰和炭灰。使用字号、间距与细边框建立层级，约 80–90% 的界面视觉面积使用中性色，蓝／青强调约 8–15%，绿色约 2–5%。比例是设计参考，不按像素强制计算。

界面优先纯色；Logo 保留自己的渐变。普通按钮、卡片和页面背景不扩散使用品牌渐变。

## 两套主题的语义映射

- **暗黑**：主要动作使用亮青，按钮文字使用深蓝墨色；链接、选中和焦点使用青色阶；成功文字使用原始品牌绿。背景维持 `#16181B`，表面 `#1D2024`，抬升表面 `#24282E`。
- **明亮**：主要动作使用深蓝，按钮文字为白；信息和连线使用深青；成功文字使用深绿 `#36540C`。背景维持 `#F5F6F8`，表面为白。
- 两套主题共享结构、语义 token 和交互，不复制组件、不按主题拼接硬编码颜色。
- 图形、状态与控件同时使用文字、形状、图标或描边辅助识别，不能只依赖颜色。

组件只使用现有语义变量，如 `var(--accent)`、`var(--accent-solid)`、`var(--on-accent)`、`var(--green)`、`var(--danger)`、`var(--surface)`。不要在组件中直接使用 HEX，也不直接按“第几档蓝色”决定组件用途。

## 功能扩展色

Logo 没有橙色和红色。产品仍需要以下两组颜色，明确作为功能扩展，不宣称来自 Logo：

- **警告**：待整合、修改或需要留意的状态；暗黑文字 `#F5B84A`，明亮文字 `#865710`。
- **危险**：错误、冲突和可能产生损失的操作；暗黑文字 `#FF9BA7`，明亮文字 `#B6354B`。

两组均配套背景和边框，具体值见色卡。普通信息使用蓝／青；成功使用绿；不为装饰、任意分类或制造视觉热闹而使用警告／危险色。

## 对比度与无障碍

- 正文、次级文字、状态、占位提示及按钮文字至少达到 **4.5:1**。
- 焦点、连线和必要控件图形相对画布至少达到 **3:1**。细边框不能作为唯一操作或状态提示。
- 原始亮青对白约 **2.64:1**，品牌绿对白约 **1.87:1**；二者不用作白底小号文字。明亮主题选择深青／深绿。
- 亮青实底按钮搭配深蓝墨色文字；深蓝实底按钮搭配白色。不能给亮青或绿色按钮机械套用白字。
- 透明颜色只用于已定义的选择遮罩、阴影、遮挡层与品牌辅助轮廓，必须连同实际底色验证。禁用、悬停与选中使用现有组件状态；不要以低对比度文字表达需要用户处理的信息。

## 维护与验收

1. `public/brand/palette.json` 是可交付的设计颜色目录；`src/themes.css` 是运行时颜色的唯一定义入口。两者在同一改动中同步，测试约束完整一致。
2. 增加颜色前先查现有语义。确有新用途时，先在色卡登记，再补齐两套主题并说明用途；不要临时绕过色卡。Logo 之外不新增渐变作为默认样式。
3. `npm run brand:palette` 从颜色目录重建 SVG 与可交互色卡，`npm run brand:palette -- --check` 检查导出是否过期。
4. 运行 `npm run check` 与相关 Edge 场景，同时核对暗黑／明亮、中文／英文、焦点、状态、差异和窄屏；证据写入 `.megit/verification/`。
5. 本规范与 [界面原则](UI_GUIDELINES.md)、[主题和国际化](THEME_I18N.md)共同验收。配色和资源调整不得改写用户白板、提交或仓库文件。
