# 主题与国际化开发标准

本规范适用于 MeGit 的所有用户可见功能，包括白板、仓库面板、弹窗、错误、空态、提示、无障碍名称及后续 Windows 外壳。

## 用户行为

连线路线编辑的工具、控制点名称、操作说明和自动路线恢复使用 `routing` 中英文资源；控制柄与焦点复用 accent／surface／focus，几何在 tokens.css 定义，不新增颜色。用户关系条件、名称及 Git 引用不翻译；两主题、键盘和粗指针共用同一编辑器。

路线吸附复用全局 snappingEnabled 浏览器偏好与 accent 参考线，无新增颜色、工作区字段或偏好。routing.pointHelp／segmentHelp 同步提供中英文的横竖对齐与 Alt 跳过说明；设计规范实际编辑器和两主题共用同一实现。

流程步骤、形状选择、连接条件编辑与只读说明使用 `flowchart` 中英文资源；用户步骤名称、摘要、命令及条件原样保存。矩形、菱形与圆角起止共用现有表面、边界、文字和焦点语义色，流程线不按主题复制组件，也不将结构性的“结束”着为已完成的成功状态。设计规范实例复用真实步骤图形。

首次打开使用暗黑主题和简体中文。左下角齿轮打开“偏好设置”；窄屏入口在画布右侧竖栏。暗黑／明亮与界面语言独立切换，立即生效，无需重启服务。首批语言为简体中文与 English。

偏好以版本 1 保存在当前浏览器、当前来源的 `megit.preferences`，包含主题、语言、`navigationCollapsed` 桌面导航折叠选择、`inspectorWidth` 详情区域宽度与 `snappingEnabled` 自动吸附开关。旧配置缺少字段时默认展开导航、详情宽 365px、吸附开启；实际详情宽始终限制为窗口的 2/3，窄屏不压缩每列内容。刷新后恢复偏好，其他同源页面会同步；清除浏览器数据或换浏览器、域名、端口后恢复默认。浏览器禁止存储、空间不足或配置损坏时给出提示，本次选择仍可使用。白板配置保存在服务数据目录，两者互不覆盖。

仓库名、流程名、自定义关系名、分支名、提交说明和文件内容属于用户数据，切换语言时原样保留。空的关系名称表示使用当前语言的默认类型名称；已有名称不迁移、不推测翻译。

打开的详情、抽屉、只读窗口、提交草稿、分支视角及滚动等浏览状态以版本 1 保存在当前标签页的 sessionStorage 键 megit.view-state，刷新恢复，多个标签页独立。记录损坏或不可保存的提示使用 viewState.invalid/unavailable 双语资源及现有状态样式。用户分支名和草稿原样保存，时间继续用 Intl；两主题不新增颜色或重复组件。

## 主题开发流程

桌面导航折叠时，「我的工作流」与「白板中的仓库」通过图标右侧的按需列表查看，选择后保持折叠；浮层只保存当前会话开关，不新增工作区或偏好字段。标题、空态、关闭入口及无障碍名称同步中英文，复用语义表面、边界、选中与状态颜色。工作流名、仓库名和分组名原样显示，仓库头像使用既有本机资源。两主题检查键盘开关、外点关闭、长列表内部滚动、长名称及粗指针命中目标。

分支树与点选详情共用同一套布局和主题 token，枝梢、曲线、HEAD 实心方形及比较状态不使用组件内色值。树干线宽为树枝三倍，尺寸在共用 token 中定义；分支名称标签与 +X 折叠数量的局部说明和总帮助同步中英文。分支树文案在 `branch-tree-zh-CN.ts`／`branch-tree-en.ts` 同步维护；分支名、提交内容和引用保持原样。`/design-system` 使用同一个纯图形组件提供可更换树干、点选与缩放的本地示例。

地图工具集中于右上角，更换比较树干的窗口、确认动作、说明和无障碍名称保持中英文同步。详情标题、HEAD／树干标记及操作分区沿用现有品牌语义色；不新增装饰色或主题分支。滚轮与双指只缩放图形，工具菜单及详情使用实际可用高度与内部滚动，验收明亮英文 390px 触控和矮窗口。

尺寸、排版和组件状态遵循[产品设计规范](DESIGN_SYSTEM.md)，非颜色 token 集中在 `src/tokens.css`。运行 `/design-system` 可检查同一套实际组件的明暗主题、中文与英文；该页面只使用本地示例状态和偏好，不读取或写入工作区。

配色以 [MeGit 品牌配色规范](COLOR_GUIDELINES.md) 与 `public/brand/palette.json` 为准：深蓝、亮青、品牌绿为核心，使用配套色阶、中性色及功能扩展色。亮青／绿色原色不直接用作白底小字。运行时颜色只在 `src/themes.css` 定义，设计目录与语义主题值由测试约束一致。

1. 组件只使用 `var(--text)`、`var(--surface)`、`var(--border)` 等语义 token。`src/themes.css` 是颜色的唯一定义来源。
2. 新语义必须同时补齐 `dark` 与 `light`，命名描述用途，避免 `gray-500` 或具体色值命名。不要按主题复制组件或在页面中条件拼接色值。
3. 图表、SVG、React Flow、缩略图、表单、差异和状态同样使用 token。主题预览图使用独立的 preview token，保证切换后仍能识别两套外观。
4. 检查正文、次级文字、状态文字和差异文字达到 4.5:1；选中、错误和焦点同时有结构或图标反馈。支持减少动态效果。
5. 在暗黑／明亮各检查一遍常态、悬停、选中、禁用、键盘焦点和弹窗；不要只检查首页。

分支名称卡片通过 `--branch-selected-bg/text` 实现品牌反差选中：明亮深蓝底白字，暗黑浅中性底深蓝字。两个主题同时登记在色卡并检查文字对比度，图标和 HEAD 继承选中文字；不以额外选中框线表达状态，键盘焦点仍遵循共用提示。当前代码位置使用共用尺寸 token 的 18px 实心方形，随地图缩放。

HTML 先以暗黑背景启动，并在样式加载前同步读取有效偏好；`src/preferences/store.ts` 负责应用主题、文档语言、标题和浏览器主题色。`index.html` 中的首屏引导是颜色集中管理的唯一例外，修改默认背景或偏好协议时必须同步并检查首屏无闪白。

品牌图形作为本地图形资源保留固定配色与精简路径；完整 Logo 的图形与名称保持相同的可见高度，使用 960 × 280 的透明画布。名称使用 `currentColor`，由 `--brand-wordmark` 决定两套主题的文字颜色。应用通过 `BrandLogo` 复用独立 SVG 图形与文字分组，不复制图形路径；图形使用 SVG 图片加载，以保持切换主题时渐变稳定。导航的展开面板与折叠 Ribbon 共用组件和 `--rail` 背景，Logo 容器透明；完整 Logo 宽 84px，折叠时图形按其在完整标志中的比例缩放，图形画布约 20.79px，避免折叠后放大。展开与窄屏抽屉中，版本号以中性徽标位于 Logo 右下方，读取产品版本并提供双语无障碍名称；底部不显示本地服务行。桌面折叠／展开按钮位于画布左上角，外框距侧栏边界和画布顶部各约 12px，随侧栏边界移动；窄屏同位置显示抽屉入口。

`--brand-symbol-outline` 控制应用 Logo 图形的环境辅助轮廓：暗黑使用 80% 不透明的浅中性色，明亮使用透明色；导航尺寸下厚度约 0.5px。轮廓只处理图形的 alpha 边界，字标、品牌原色与路径不变。每个实例使用独立滤镜 ID，支持导航与帮助窗口同时显示和即时切换主题。导航顶部行高 44px，展开时帮助图标位于 Logo 右侧靠右，窄屏与关闭按钮并列；折叠 Ribbon 保留底部帮助入口。按钮复用双语名称与 tooltip。

Git 详情区域不显示额外顶部导航或白板操作底栏，各列保留标题和关闭。白板、分组、说明编辑使用共用双主题／双语 Dialog；左上角选中副工具栏的移除按钮复用登记的危险色，常态与悬停均保持红色。中间工作流面板顶部复用同一紧凑标题栏，显示原始流程名、信息与关闭入口，桌面单行和右侧同为 29px；工作流信息、关闭、重新打开及空态同步维护中英文，名称和说明原样展示。关闭只隐藏当前视图，保留内容及右侧详情；重新打开及导航入口保持可达。画布右上角为竖向操作栏，承载添加、刷新、关系、分组、详情与工作流选项；桌面检查器占位时随画布右边界移动，窄屏覆盖式检查器显示在画布控件上方。主区域以原始流程名提供无障碍名称；保存状态在底部持续可见。标题栏下方的左上开关、相邻编辑工具与右侧操作栏共用按钮尺寸、4px 内边距和顶部位置，首行按钮对齐；桌面按钮 32px、单行外框高 42px，触控按钮 44px、单行外框高 54px。编辑工具按同一尺寸避让并在窄屏换行，浮动控件继续使用既有语义颜色、双语 tooltip 和键盘焦点反馈。

## 多语言开发流程

提交点菜单、新建时锁定的版本、复制反馈及无障碍名称由 `branch-tree-zh-CN.ts`／`branch-tree-en.ts` 与双语 GitHelp 同步提供。菜单、选中描边、成功和失败使用现有语义主题，无新增颜色；宽度集中在 tokens。验收暗黑中文、明亮英文、390px 真触控、缩小后的命中区、详细提示层级和多个仓库菜单隔离，提交说明／作者／SHA 保持原文。

仓库原始资料在标题栏的「i」浮层中按需显示，复用两主题语义表面、边框和字体。Git 初学说明集中在 `git-help-zh-CN.ts` 与 `git-help-en.ts`，由 `GitHelp`／`HelpTip` 统一呈现；术语、说明、无障碍名称以及 Intl 格式化的检查／获取时间随语言即时切换。路径、分支名与提交编号保留原文。状态限制与错误不依赖帮助入口显示。

分支树工具菜单的“获取”复用现有动作与双主题 tooltip，提供 `--prune` 命令预览。中英文分支标签说明明确远端引用来自本机缓存；获取说明和成功反馈同时说明清理过期记录，本地分支与已合并历史保留。刷新仍只读本地，获取失败保持可见错误。

1. 先在 `src/i18n/locales/zh-CN.ts` 添加稳定语义键，再同步 `en.ts`。英文资源结构由 TypeScript 约束。禁止把整句中文当作键或在组件中按语言分支。
2. React 使用 `useTranslation()` 与 `t('repository.clean')`。非 React 格式化函数使用同一个 `i18n` 实例，避免独立语言状态。
3. 整句翻译，不拼接词序。例如 `t('repository.commitFiles', { count })`；英文需要 `_one`、`_other`，其他语言按 i18next 的 CLDR 规则提供必要形式。新增键的插值参数在所有语言中一致。
4. 日期、数字和相对时间使用 Intl，语言来自当前 i18n 语言。路径、SHA、比例等技术表示可保持原格式。
5. 所有按钮的 `aria-label`、提示的 `title`、输入提示、对话框标题和 React Flow 的操作说明同步接入。CSS 不承载固定语言的文本；布局必须容纳英文展开后的长度。
6. 服务错误先在 `shared/messages.ts` 定义稳定代码，服务端抛 `AppError('directoryMissing')`，前端用 `formatError` 解释。不要把翻译后的错误永久存进状态；保留代码以便切换语言后重译。原始 Git 输出作为技术详情保留并脱敏。

新增语言时：新建本地资源文件，在 `src/i18n/index.ts` 注册资源，在 `src/i18n/languages.ts` 注册代码和自称；补齐所需复数形式并通过资源检查。不得运行时从 CDN 拉取翻译。语言自称（简体中文、English）是有意保留的原文。当前两种语言均为 LTR；未来增加 RTL 语言时需同时验收文档方向与画布操作，不能只翻译文本。

## Git 学习资源

仓库头像设置的中英文集中于 `repository-avatar-zh-CN.ts` 和 `repository-avatar-en.ts`，目录名和图片相对路径保持原文。图片使用原始项目颜色，默认图标、容器、边界、选中与错误使用双主题语义 token；不按主题重复组件，不从远端加载图标。头像是仓库属性，存于工作区，与浏览器主题和语言偏好分离。

图解课堂的中英文集中在 `learning-zh-CN.ts` 与 `learning-en.ts`，由主资源注册并接受同样的键、插值和类型检查。图形、短提示、课程、控制按钮、拖动帮助和读屏状态同步切换；虚构文件名、命令、分支名、C1 等提交编号保持原样。图形只使用现有双主题语义 token，不加载远端素材。解释动画只改变 transform／opacity，减少动态偏好下去除位移；图形替代文本包含当前 HEAD、分支和父提交，远端课分别说明本地／缓存／远端状态。课程、步骤、窗口和内部滚动位置写入当前标签页浏览记录，刷新恢复后暂停，不写浏览器偏好或工作区。

可复用演示的操作标题集中在 `learning.preview.titles`，短提示和替代文本继续引用原课堂资源。高级提示与静态预览共用紧凑布局和 `--learning-preview-width/height`，不按主题复制组件或引入新颜色。减少动态时直接展示海报帧并移除子图形动画。设计规范页提供 14 类操作、文字／图标按钮和静态图解，支持即时切换主题与语言；素材与接入契约见 [GIT_LEARNING_MEDIA](GIT_LEARNING_MEDIA.md)。

## 开发门禁与验收

```powershell
npm run check:standards
npm test
npm run lint
npm run build
npm run test:e2e
```

`check:standards` 检查双主题 token 契约、组件散落色值、未定义的样式变量、硬编码 JSX 和无障碍文案；类型检查约束翻译键。单元测试校验语言键和插值完整性、复数、时间、偏好回退及颜色对比度。新增语言所需的复数形式应在资源检查中按 CLDR 分组校验，不删除原有键或将非英文复数强行简化。

Edge 场景覆盖首次默认值、独立切换、刷新恢复、英文应用错误、窄屏入口、两主题面板与差异；同时保留真实暂存／提交／获取／拉取的回归。自动检查不能代替两主题的视觉核对。

## Git 命令提示验收

`gitCommands` 维护命令阶段、只读、缺少参数与无需 Git 的双语说明，`CommitEvent` 保留用户提交说明并使用 Intl 日期。命令预览只使用既有语义颜色与等宽字体，长参数换行且可选中；普通提示默认等待共用 token 的 500ms，键盘立即显示。两主题、中英文、窄屏及特殊 PowerShell 参数均属于验收范围。
