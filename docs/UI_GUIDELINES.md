# MeGit 界面开发原则

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

这三项原则适用于每个新页面、组件和交互，必须与[主题和国际化标准](THEME_I18N.md)一起验收。

页面骨架、尺寸、组件、列表、表单、反馈与白板交互的具体规则见[产品设计规范](DESIGN_SYSTEM.md)。启动后可在 `/design-system` 检查产品实际组件的状态；色卡页面提供同一入口。

1. **用布局解释。** 用分组、对齐、位置、图标和状态表达关系。去掉重复标题、装饰性英文标签、反复出现的环境说明，以及“你可以……”式常驻教学。字段名、可辨识的主要动作和关键状态仍应清楚。
2. **说明按需出现。** 图标操作必须有当前语言的无障碍名称；用途和简短限制放到 tooltip，悬停及键盘聚焦均可查看，Escape 可收起。不要用 tooltip 代替字段名、必要状态或错误提示，也不要把交互内容放进 tooltip。
3. **渐进式披露。** 首层只呈现完成当前任务所需的信息。节点点击后显示详情，关系先显示结果，再展开比较依据；较长说明进入帮助或可展开区。无法判断的原因、保存失败、冲突和可能影响操作的限制保持可见。

## 实现约定

- 颜色遵循 [品牌配色规范](COLOR_GUIDELINES.md)，优先中性色组织结构，蓝／青表达交互，绿表达成功；警告和危险仅用于对应状态。所有色值通过双主题语义 token 使用。

- 图标按钮优先复用 `IconButton`，内置 `Tooltip` 和 `aria-label`；特殊画布控件可单独使用 `Tooltip`。移动端不依赖悬停，保留主要动作与帮助入口。
- tooltip 使用局部短句并接入 i18n，两主题使用同一套语义 token。复杂说明或需要点击的内容改用弹出面板、详情区或帮助。
- Git 初学说明复用 `GitHelp`／`HelpTip`，以“标题 → 含义 → 操作结果”提供两小段纯文本。问号支持悬停、主动键盘聚焦与点击固定；同步问号可同时查看获取／拉取／推送，文件分组问号可查看暂存／取消暂存。详细提示可移入阅读和内部滚动，键盘使用方向键、PageUp／PageDown、Home／End；内部焦点转移保留内容，Escape 返回入口。交互内容仍放在独立浮层，避免每项都增加常驻教学段落。
- 仓库路径、完整 HEAD、远端及检查／获取时间通过标题栏关闭按钮左侧的 `RepositoryInfo` 信息入口按需查看。原始字段可选择复制，技术术语有局部说明；未配置远端、未设置跟踪、脱离分支和读取失败等必要状态直接可见。关系无法核对的原因始终展示，不藏进可折叠的比较依据。
- 所有 tooltip 共用浏览器顶层显示与视口避让，不能被导航、画布、滚动容器或原生模态裁切；不在单个调用处另加 portal 或堆高 z-index。
- 临时浮层复用 `Tooltip`／`PopupMenu`：激活按钮立即隐藏提示，自动恢复焦点不重新弹出；主动悬停和键盘聚焦仍可查看。菜单在外点、焦点离开、Escape、执行动作或打开其他浮层时收起；外点和 Tab 保留新目标焦点，Escape 返回触发按钮。弹窗与抽屉按层级响应 Escape，异步忙碌保护继续生效。延迟恢复焦点只在当前焦点已回到页面时执行，不覆盖用户已经移动到的新目标。
- 表单先显示必要字段，说明靠近相关字段按需查看；提交后的错误显示在表单内，不能只弹一下即消失。
- 通过字号、间距与细边框建立层次，不以额外提示条和重复文案填充空白。
- 发布前检查默认状态是否简洁，进一步查看是否能找到完整依据；检查英文展开、窄屏、键盘和两种主题。删去界面文字时同步检查无障碍名称仍完整。
