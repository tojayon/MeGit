# MeGit 主题与国际化实施计划

**目标：** 建立后续所有界面开发必须遵守的主题和多语言基础，默认呈现参考图中的深灰开发工具风格，并可切换明亮主题。

**架构：** 使用语义化 CSS token 在同一套组件上实现 dark / light。使用 i18next、react-i18next 和本地语言资源，以稳定键名统一界面、错误与时间格式。版本化的本机偏好与流程数据分开，启动时同步应用主题，避免先亮后暗。

**范围：** 首批简体中文与英文，语言与主题独立切换并持久化；设置入口始终可达。国际化覆盖所有应用自有 UI 和 API 错误，Git 原始输出作为技术详情保留。仓库、工作流、连线自定义名称及提交内容不翻译或重写。

## 执行步骤

1. 建立偏好、翻译资源完整性／插值／复数、主题 token 与标准检查的失败测试。
2. 实现版本化偏好、首屏主题初始化、i18next 及类型化资源；新增设置面板。
3. 将现有组件的文案、时间与无障碍名称迁移到翻译资源。服务错误返回稳定 code 和参数，客户端按当前语言解释。
4. 将全部颜色迁移到 `src/themes.css`，样式只引用语义变量；默认暗色、保留明亮。统一 React Flow／缩略图／弹窗／差异／状态颜色。
5. 新增 Edge 场景覆盖暗色首次启动、主题／语言独立切换、刷新恢复、英文错误、两主题的弹窗和窄屏；保留原 Git 操作回归。
6. 更新 AGENTS 和开发文档，运行测试、标准检查、lint、build、Edge，重启本机预览并截图核对。保留 `.megit/workspace.json` 的用户布局与所有真实仓库内容。

## 设计取舍

- 选择 CSS token，不复制暗色／明亮两套组件，避免行为分叉。
- 选择成熟 i18next，不维护散落的语言判断；新增语言从资源注册和完整性检查进入。
- 只提供暗色与明亮两个确定的主题，首次默认暗色；系统跟随可在明确需求后增加。
- 偏好存于 `megit.preferences`，与布局存储解耦；受限或损坏的存储回退默认，并明确提示偏好无法跨刷新保存。
