# 向上生长的分支树详情方案

状态：方案草案，仅用于讨论；尚未修改产品行为或正式服务。

## 1. 目标与方案选择

仓库详情首先回答：有哪些开发分支、各自在哪里开发、相对目标分支有哪些提交、下一步如何继续或整合。文件是核对、提交和解决冲突时按需进入的资料。

根据用户修订，采用占据面板主体的“向上生长的分支树”：主要比较分支是树干，功能分支是向两侧上方延伸的树枝，提交是枝上的小节点。名称贴近枝梢，只有点击树枝时才出现浮动详情和上下文动作。保留当前最小 320px 的仓库列及多仓库横向并排，不采用文本列表作为默认视图。

不再保留“工作区／历史／分支”三套同级入口；进入仓库即看到树。浏览某条树枝只读其信息，不切换工作目录中的代码。Git 无法独立证明功能的开发、验收或完成状态，树的高度、枝长和节点数量均不能作为功能完成度。

## 2. 默认信息布局

1. 仓库标题：头像、仓库名、已有「i」信息入口、关闭。路径、完整引用、完整 SHA 和检查时间继续按需查看。
2. 树干：比较基准初始采用可识别的默认分支，用户可更换，不硬编码 main。基准的首父历史构成中心向上的主干，较旧提交在下、较新提交在上；更换基准重新布局，不执行 checkout。
3. 树枝：其他分支从可核对的共同历史位置向左右上方平滑延伸，名称贴在枝梢，当前目录所在分支使用 HEAD／当前标记。可使用用户填写的简短功能名作为枝梢标签，完整分支原名在可访问名称、tooltip 与详情中保留；没有功能名时使用分支原名。其他独立工作目录用小型目录标记表示。远端引用按需展开，与本地分支的跟踪资料区分。
4. 节点与合流：实心小节点表示已提交记录；未提交改动以枝梢旁的独立空心标记或状态标识表示，不伪造提交。真实 merge 的第二父边让枝条向上汇入树干；仅有祖先包含证据时显示“已包含”，不能补画不存在的合并边。
5. 点选树枝或枝梢后高亮对应路径，其余枝条弱化；浮层只展示该分支的对比、同步、工作目录和动作。必要冲突／错误通过对应分支旁的明确标记持续可见，详情解释保持可访问。不在树下常驻大段记录、统计卡片或文件列表。

树形是空间表达，底层保留 Git 的有向无环图。分支之间可以共享历史、互相合并或没有共同历史，不能一律画成直接源于主干。枝条相交处使用跨线间隔，只有真实提交节点才表示连接；同一提交上的多个分支引用共用节点。没有真实创建记录时，共同提交不标为“分支创建点”。已删除的历史分支名称不能从 Git 提交图推测。没有共同历史的引用以独立小树显示，并解释原因，不强连树根。

“本分支独有 6 条提交、main 独有 2 条提交”描述两个提交集合的差异。“待推送 2 条提交”针对该分支的上游引用。两者使用不同标签和帮助，不共用一个模糊的“领先／落后”计数。

## 3. 展开后的动作

### 当前工作目录所在分支

- 有改动时主要动作是“提交改动”，进入当前工作目录的提交流程；默认不铺文件列表。
- “比较”查看相对目标的提交和变化；“推送／拉取”仅在上游和状态允许时出现，明确显示操作分支。
- 暂存／未暂存分组及逐文件差异保留在“查看改动文件”中。提交流程提供改动范围核对，不盲目把所有修改加入一次提交。

### 在其他独立工作目录打开的分支

- 主要动作是查看／打开该工作目录，使用户和相应 AI 会话在正确位置继续开发。若暂未提供操作系统打开能力，先提供路径与复制，不显示无效按钮。
- 目录的未提交修改与进行中的操作归属于该目录，不能按整个仓库的修改数量复制到所有分支。
- 当前目录不能强行切换到已被其他 worktree 占用的分支。

### 尚未打开工作目录的分支

- 优先提供“在独立目录开发”，建立或选择独立 worktree；“在当前目录切换”作为次级明确动作，保留既有干净工作区检查。
- 新建分支从所选基准或明确引用创建，可同时创建独立目录；不自动启动 AI 会话或猜测用户使用的开发工具。
- 删除放在更多动作中，保留现有安全条件、明确确认与 Git 原生保护。

分支上的功能名称或说明可以由用户手动填写；不根据文件数量或最近提交自动判断“功能完成”“可以发布”。

## 4. 比较与整合

点击“比较”后，直接在树上突出源枝、目标树干和双方独有的提交，共同历史降低强调；浮层标明源 → 目标及各自独有数量。点击提交再看提交说明，文件与逐行差异属于更深一层。多个开发分支与同一基准之间的比较可缓存已解析 SHA 对应的结果。

“整合到…”展示清晰的源 → 目标、实际接收合并的目标工作目录、未提交状态和检查结果。无法确认目标目录、正在进行其他 Git 操作或状态过期时，直接显示限制原因。

“已经包含”“可以快进”“尚未检查”“发现冲突”必须来自对应检查。提交数量不能证明没有冲突；合并预检查也不能证明功能通过测试，推送成功不等于部署完成。执行时重新校验源／目标 SHA、目标分支及工作目录状态。

第一轮不提供隐式切换并合并、自动 stash、强制删除或自动改写历史。整合预览如绘制拟合流线，必须采用带“预览／未执行”标识的虚线，不能与实际提交边混淆；执行成功并刷新真实父子关系后才绘制实际合流。冲突发生后提供明确的持续状态和处理入口，文件层在此时成为必要内容。

## 5. 渐进式披露与交互规则

- 常态：树干、树枝、提交节点、枝梢分支名、当前目录及必要状态的小型标记。
- 点选：高亮路径，浮层显示明确基准的提交数量、最近提交、远端同步、工作目录和当前可执行动作。
- 专项查看：比较历史、文件差异、提交范围和冲突。
- 「i」或更多：仓库路径、完整 SHA、远端资料、技术依据。

点击分支与实际切换是两个独立动作；查看比较不得修改代码。双主题、简体中文／英文、键盘、触控和减少动态与现有规范一致。帮助解释分支、工作目录、上游、比较基准、提交、推送和整合之间的关系，复用现有详细 tooltip 与图解内容。操作条件、错误和未知原因持续可见。

右侧继续只承接 Git 功能，不增加白板删除入口、仓库标签导航或新的常驻底栏。区域仍可调宽到窗口的 2/3，各仓库列保留最小宽度和横向浏览，打开详情不改变白板视角。窄列通过错开枝梢标签、折叠较旧连续提交和按需展开降低密度；不缩小文字硬塞整棵树。枝条很多时允许平移／缩放及定位，使用独立的“适应分支树”动作，不联动画布。分支和提交提供原生可聚焦入口、充分触控范围及完整名称，悬停只补充说明。

## 6. 与当前实现的衔接

现有功能可复用：分支创建、切换和安全删除，当前工作目录的暂存／提交／同步，仓库信息浮层、帮助、双语主题与多详情容器。

需要新增的数据能力：任意本地／远端分支的按需历史与比较；每条分支自己的上游与独有提交数；linked worktree 的目录映射与各目录状态；后续的 worktree 创建和受控合并。现有 history 接口没有分支参数，当前 ahead／behind 和文件数组属于当前工作目录，不能直接拿来展示所有分支。

分离三个对象：仓库身份、完整分支引用、工作目录上下文。linked worktree 通过共同 Git 目录识别归属，保留原有登记路径和白板节点引用，不悄悄合并或迁移用户节点。多个 worktree 的写操作同时考虑共同仓库和实际目录，避免互相竞态。

默认摘要只请求分支元数据、状态计数和必要错误。文件路径与 diff 按需分页读取，避免数百个变更文件随每次状态刷新传输；分支比较也不对全部分支重复计算。外部工具修改引用后作废相关缓存。

## 7. 建议实施顺序与验收

1. 先完成向上分支树、可更换树干、枝梢选择、路径高亮、渐进浮层和按需文件层；增加明确基准的只读图上比较，保留现有创建／切换／删除及提交功能。
2. 接入独立工作目录识别与创建，使多个功能和 AI 会话可在不同目录并行开发；确认各目录状态不会串到其他分支。
3. 完成目标目录明确的整合流程和分支收尾，复用比较结果与安全校验。

验收重点：树干可以更换且不切换代码；节点与真实提交、父边、引用对应；真实合流和预览区分；多父提交、同一提交多个引用及不同根正确呈现；数百文件改动下仍能迅速找到分支；各分支同步信息独立；工作目录映射真实；冲突和过期状态不隐藏；空仓库、detached HEAD、无上游、远端已删除引用和未知共同历史可解释；窄屏文字不缩小、标签不重叠。相关 Git 操作仅在独立目录和虚构仓库中测试。

用户已确认向上生长的树形方案，第一阶段已实现并更新本地预览。实施及验收见 [分支生长树实施记录](2026-11-17-branch-tree-implementation.md)；独立工作目录创建与写入式跨分支整合继续作为后续阶段。
