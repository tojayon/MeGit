# 可连接维护流程图实现计划

目标：在真实的「MeWiki 双版本」白板画出起点、职责判断、两条开发入口、公共整合、服务验收、构建、人工发布与失败回路。

架构：保留仓库节点与 Git 关系。人工说明可选步骤、判断、起止形状，增加独立流程连线；流程连线不参与 Git 状态判断，不执行命令。兼容现有 version 1 数据，沿用保存冲突、主题、国际化、撤销及导出。

1. 先添加持久化、端点校验、删除清理、历史测试并观察失败。
2. 扩展 FlowNote 与 Board.connections，补服务端校验、白板操作和几何。
3. 增加共享步骤呈现、流程线、步骤及连线编辑，复用说明入口和端口拖连；同步设计规范真实示例、双语文案及导出。
4. 按维护文档与参考对话设计紧凑的有向流程，步骤详情承载命令，主图清楚标出通过、失败与回流。
5. 使用独立虚构仓库做 Edge 验收；执行 npm run check 和相关 npm run test:e2e。
6. 备份并通过正常接口仅更新目标白板，保留其他内容与并行编辑；构建后核对身份，仅更新 MeGit 正式预览，实际回读并核验明暗主题。

本轮直接在当前包含用户已有改动的工作区完成，保留它们，不提交或推送。文档中的维护命令仅作为流程内容，不执行源码同步、发布或真实资料迁移。
