# 获取远端并清理过期引用

用户已确认：GitHub 删除分支后，MeGit 获取远端应清理本机过期的远端标签；本地分支与已合并提交历史保留。刷新状态仍只读本机，不隐式联网。

- 共用 `actionArguments` 为获取增加 `--prune`，执行与命令预览保持一致。
- 分支树工具菜单增加现有“获取”动作，不必先打开当前分支详情；保留忙碌、错误及刷新处理。
- 中英文帮助解释远端引用是本机记录、获取会清理过期引用、历史与本地分支保留。复用现有主题、菜单及 tooltip。
- 使用临时裸远端重现远端分支删除，验证普通读取保留缓存、获取清理缓存、本地文件与分支不变、合并父关系不变；Edge 验证两主题双语、命令提示与地图更新。
- 运行 `npm run check` 和相关 `npm run test:e2e`，记录证据；不操作真实仓库的远端引用，不提交或推送。

## 指定分支获取规则失效的修复

用户后续明确同意修复 MeWiki-Server：备份该仓库配置，将 origin 两条指定分支规则换为标准的 `+refs/heads/*:refs/remotes/origin/*`，显式获取 origin 并清理。前后校验 HEAD、本地分支、暂存区字节与未提交状态。此授权仅适用于这个已核对的仓库；MeGit 不自动改写其他仓库的定向获取规则。

产品识别 fetch 的 `couldn't find remote ref refs/heads/` 诊断，返回稳定 `remoteRefMissing` 错误及脱敏原始信息，中英文解释获取规则失效与处理办法。地图工具动作错误在整个面板可见，不依赖用户先选分支。临时裸远端复现定向获取失败，再修正规则验证清理成功，两主题双语 Edge 覆盖错误和恢复流程。
