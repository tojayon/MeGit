# 仓库卡片整理

用户明确要求两行身份区（跨行图标、名称、分支和修改数）与分割线下单行操作（全部暂存、消息、输入内AI、提交）。保持节点宽度和现有白板／端口行为，使用真实 RepositoryCard 复用到设计规范。

卡片与详情共享持久草稿和仓库级忙碌锁，复用现有 Git API、安全校验和命令提示。暂存全部当前未暂存文件；提交仅消费暂存区，不隐式暂存。错误直接显示，成功后刷新并仅在提交成功清空输入。AI 按钮是可聚焦、不可执行的开发中占位。两主题双语和触控命中保持统一。

先用独立虚构仓库编写卡片红测，再实现和验证真实暂存提交、失败保留、草稿同步、重复保护、刷新、双主题、窄屏以及头像／工作流／设计规范回归。保留并行 AI 改动，不提交推送。
